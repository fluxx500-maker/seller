# seller.bz — пакет для работы над визуалом в Google AI Studio

Это отдельная дизайн-версия актуального интерфейса, а не перенос рабочего backend.
Node.js >= 20; Python, база данных, API-ключи и npm-зависимости не нужны.

## Импорт

Официально описанный путь Google AI Studio на 09.10.2026:

1. Распакуйте ZIP. В корне должны лежать `package.json`, `server.mjs`, `manifest.json`, `public/` и `pages/`.
2. Загрузите содержимое этой папки в отдельный GitHub-репозиторий (можно приватный).
3. В AI Studio → Build → `+` / Add files → **Import from GitHub** выберите этот репозиторий.
4. Вставьте текст из `AI_STUDIO_PROMPT.txt` и укажите, что хотите изменить визуально.
5. Команда запуска: `npm run dev`. Порт 3000, либо переменная `PORT`, либо `npm run dev -- --port 3000`.

Если в вашей версии редактора есть **Upload ZIP**, можно попробовать загрузить этот архив в файловую область Code. ZIP нужно именно распаковать как проект, не просто приложить к чату как контекст. Прямой ZIP-импорт не подтверждён текущей официальной инструкцией; гарантировать наличие этой кнопки нельзя. Подтверждённый путь — GitHub.

Источник: https://ai.google.dev/gemini-api/docs/aistudio-build-mode

Пакет проверяется локально; авторизация и импорт в ваш аккаунт Google/GitHub не выполнялись. Ничего не опубликовано.

## Локальный запуск

```sh
npm run dev
```

Откройте http://localhost:3000. Для другого порта: `npm run dev -- --port 3001`.

## Что внутри

- `public/static/studio.css` — актуальный UI kit.
- `public/static/pane-layout.css` — адаптивность и компактная однострочная шапка второй панели.
- `public/static/style.css`, `themes.css` — базовые компоненты и темы.
- `public/static/*.js` — исходные взаимодействия: графики, таблицы, меню, split view.
- `pages/1/`, `pages/2/`, `pages/3/` — Ozon, Wildberries, Яндекс Маркет. Внутри `full/` и `pane/`: обычная и правая панели.
- По 18 страниц на площадку и режим: 17 основных разделов + один пример карточки товара. Итого 108 HTML-файлов с синтетическими данными.
- `reference/jinja-templates/` — исходные шаблоны для понимания структуры и последующего переноса изменений. Node-сервер их не исполняет.
- `server.mjs` — небольшой сервер демостраниц; `manifest.json` — маршруты.
- `public/preview.js` — ограничения дизайн-прототипа.

## Что работает и что является макетом

Работают навигация по включённым разделам, выбор площадки, независимая правая панель, её размеры, меню разделов, тема, клиентский поиск/сортировка таблиц и просмотр графиков.

Данные — зафиксированный снимок демонстрационной базы. Период не пересчитывает цифры: календарь открывается для визуального редактирования, но применение дат блокируется пояснением. POST-формы не сохраняются, настройки плиток не сохраняются между перезагрузками, XLSX не экспортируется. Каждая площадка содержит одну примерную карточку товара: разные ссылки товара открывают этот пример. Учётная запись, биллинг, управление доступами и другие невключённые маршруты показывают страницу ограничения. Не используйте пакет как производственный сервис.

В архиве нет `.env`, `.git`, SQLite, паролей или ключей исходного окружения. Служебные CSRF-значения заменены на `design-preview`. Шрифты, иконки и короткое видео тура включены локально.

## Как работать с Gemini и вернуть результат

Сначала меняйте общие CSS — они применяются ко всем страницам. Если меняете HTML-компонент, обновите соответствующие варианты трёх площадок и двух режимов. Текущий проект не React: не переписывайте его целиком без отдельного решения.

Сохраните `data-*`, ссылки, классы-хуки JS, имена полей и правильную семантику. Не превращайте финансовые значения и товарные списки в неподвижный скриншот. Во второй панели магазин, раздел и период остаются в одной строке; минимум панели 360 px.

После работы скачайте ZIP из AI Studio и отправьте обратно вместе со списком изменений. CSS можно переносить непосредственно; HTML-изменения нужно перенести обратно в Jinja, сохранив серверные выражения. Новый дизайн не изменит исходный проект автоматически.
