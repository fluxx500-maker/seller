Работай с импортированным проектом seller.bz. Не создавай новое приложение с нуля и не заменяй существующие экраны общей демо-панелью.

Сначала прочитай README.md, package.json и server.mjs. Это Node.js-проект без зависимостей, с готовыми HTML-страницами и настоящими стилями текущего интерфейса. Запусти npm run dev на порту предпросмотра (server.mjs поддерживает PORT и --port). Python и база данных не нужны. Никакой Gemini API key также не нужен.

Моя цель — поработать над визуалом интерфейса, сохранив структуру продукта и данные. Основные файлы: public/static/studio.css, pane-layout.css, style.css, themes.css, pages/. reference/jinja-templates/ содержит оригинальные шаблоны для будущего переноса, но не используется в предпросмотре.

Сохраняй все существующие разделы, сводки Ozon / Wildberries / Яндекс Маркета, таблицы, графики и разделение окна. Во второй панели магазин, раздел и период должны помещаться в ОДНУ компактную строку, а сама панель должна иметь независимый выбор магазина и раздела. Цифры не должны выходить за карточки при изменении ширины. Сохраняй тёмную тему и доступность с клавиатуры.

Не добавляй реальные API, авторизацию, оплату или новые базы данных. Данные фиксированные синтетические; ограничения прототипа описаны в README. Не изображай успешное сохранение или пересчёт, если backend отсутствует. Не удаляй предупреждения прототипа ради видимости работоспособности.

До изменений коротко опиши текущую структуру и план. Затем меняй только согласованный визуал. Проверяй все затронутые страницы и split mode, особенно панели 360 px и 680 px. Общие стили применяй ко всем страницам; изменения разметки синхронизируй для full/pane и трёх площадок. Не переписывай на React без моего явного запроса.

В конце перечисли изменённые файлы и что понадобится перенести обратно в исходные Jinja-шаблоны.
